# Positional extension defaults yield to other bindings

The extension navigation defaults (⌘⌥1–9 on macOS, Ctrl+Alt+1–9 on Windows/Linux) are computed from the extension load order, so they move whenever extensions are added, removed or reordered. An inherited positional default that would collide with a customization, a stable factory default or the menu opening yields: that action is left unbound and highlighted as unbound, and the other binding keeps working. The outcome is not persisted (unlike the new-default rule of ADR 0001, which settling records as an explicit unbinding), so the action regains its default as soon as the key is free again. This keeps a reorder from making a saved profile invalid or silently taking over a researcher's key, at the cost of an extension occasionally showing as unbound until the researcher binds it or frees the key.
