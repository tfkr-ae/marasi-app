# HTTP editors highlight bodies with a Lezer grammar and parseMixed

Every raw HTTP editor in the app—the Ledger and Armory drawers, Logbook linked pairs, Launchpad drafts, responses and Compare diffs, Checkpoint held requests and responses, the Armory template editor, and extension `http` editors—shares a CodeMirror 6 Lezer HTTP language that parses the start-line and headers (including Marasi's HTTP/2 text form and `:pseudo-headers:`) and mounts the body language through `parseMixed`. Supported body formats are JSON (including `*+json`), HTML (`text/html` and `application/xhtml+xml`, with embedded `<script>` JS and `<style>` CSS), XML (including `*+xml`), JavaScript, CSS, and `application/x-www-form-urlencoded`, backed by the official `@codemirror/lang-json`, `@codemirror/lang-html`, `@codemirror/lang-xml`, `@codemirror/lang-css`, and `@codemirror/lang-javascript` packages plus a lightweight form parser. Body highlighting is permissive so truncated or fuzzed payloads are never painted red, while malformed HTTP start-lines and header lines keep their existing error highlighting.

Body language resolution runs live from the editor text in three steps: (1) a binary prefix guard skips body highlighting if the body starts with non-text control bytes (such as raw compressed `Content-Encoding: gzip` bytes); (2) a recognized `Content-Type` header wins unless the trimmed body prefix unmistakably contradicts it and strongly matches another known format (for example, an HTML error page served under `application/json` or JSON served under `text/html`); (3) when `Content-Type` is absent or unrecognized (`text/plain`, `application/octet-stream`, or an unknown MIME type), a short leading prefix (~256 characters) is sniffed for JSON, XML, or HTML, leaving everything else unhighlighted. Under `Settings → Syntax highlighting → Auto`, the HTTP head stays highlighted and only body highlighting is skipped once the body exceeds 75,000 characters (`Disabled` turns off all highlighting; `Enabled` highlights regardless of size), applied consistently across all raw HTTP editors. Armory template syntax (`@@fallback@@` markers with chained `.fn()` calls, Go template `{{...}}` actions, and framed message-form separators with protobuf text form or JSON bodies) is scoped strictly to Armory's `TemplateEditor` so ordinary HTML or JavaScript responses containing `{{...}}` or `@@...@@` are never mishighlighted as template placeholders.

We considered extending the existing legacy `StreamLanguage` mode (`httpMode.js`) to delegate body lines to `@codemirror/legacy-modes` with no new dependencies. Legacy stream modes tokenize linearly from line 1 rather than incrementally by viewport, handle embedded `<script>` and `<style>` blocks inside HTML poorly without custom multiplexing, and produce no syntax tree. We also considered strict `Content-Type`-only resolution with no sniffing or mismatch override, and keeping the whole-message 75 KB cutoff in `Auto`, but real proxy traffic routinely carries mislabeled error pages or missing headers, and losing header highlighting on large responses made large pairs harder to scan.
