# Traffic ledger

## Sub-features

- HTTP request/response rows, and WebSocket upgrade rows whose badges column shows the upgrade state
- The WebSocket modal opened from an upgrade: Stream, Checkpoint, Inject, and Connection tabs
- Indexed query search, content-type exclusions, and loading older query pages on scroll
- Request detail in the drawer, notes, highlights, and handoff to Launchpad, Armory, or Logbook

## How to get to it (user POV)

Select the rail item titled `Ledger` or press `Command+2`. The page is the sitemap dock (`.lp-dock`, strip `.lp-strip` labelled with the chosen sitemap node without its scheme, else `Sitemap`, when collapsed; `⌘\` toggles it), a one-row toolbar (`.ledger-toolbar`) with `#searchBox` (placeholder `Search traffic…`), a `Saved queries` button (`#ledgerSavedQueriesButton`), a `Highlights` button (`#ledgerHighlightsButton`), a `Marks` button (`#ledgerMarksButton`) and a `Types` button (`#ledgerTypesButton`, badge `#ledgerTypesHiddenCount` reading `N hidden`) whose menu (`#ledgerTypesMenu`) holds the find box `#ledgerTypesFind`, group chips (`.ledger-types-group`, `data-state` `shown`/`partial`/`hidden`), `#ledgerTypesSource` (`This project's own list` or `Following the app default`) with `#ledgerTypesReset` (`Reset to default`, confirm modal) when the project has its own list, and Shown/Hidden rows (`.ledger-types-row[data-type="…"]`, a checkbox and a pair count; the no-response row has `data-type=""`, reads `(no response)` and is always shown), the windowed table (`.ledger-table`, rows `.ledger-row`, columns `# · badges · Time · Method · Host · Path · Status · Type · Size`); `#` is Marasi's pair number (row field `Number`): it follows capture order, never changes and leaves gaps for deleted pairs, so query results and other sorts show each pair's own number. The default sort is `number desc`, and `#` sorts by `number`. `number = 10` (and `!=`, `<`, `<=`, `>`, `>=`) is a query field. `cmd+shift+o` (Open request, drawer open or closed) asks for a number and opens that pair in the drawer, scrolled to the middle of the table when it was out of view (check with `#ledgerPosition`: request N is row count − N + 1 in the newest-first live view). The query never changes: under a `number` sort a pair that isn't loaded is read in with the rows around it, and paging goes on from there; under another sort a pair that isn't loaded opens in the drawer on its own (the table stays as it is), and the drawer's next/previous go on from it by # (next is the next pair down, previous the next one up) until they reach a loaded row; a pair the results don't hold (the query or the type filter leaves it out) still opens, on its own in the drawer with the table untouched, and only a number with no pair in the project toasts `No request N in this project`. Its dialog submits with `Continue`, not Enter. Check stored numbers with `sqlite3 <project> "select number, request_id from pair_number order by number"`; the focused row has a primary frame (`.ledger-focus`), which drops its top edge (`border-t-0`) when the row sits right under the header and its bottom edge (`border-b-0`, the row's own border transparent) when it sits on the open drawer's border; the status bar's `#ledgerPosition` reads ` · rows A–B` (the rows of the results in view; absent when the window's offset is unknown); Type shows a short name (`x-protobuf`, `json`), and hovering it (`.ledger-type`) shows the full content type in `.ledger-type-tip`, hung from the cell's right edge, and the status bar (`.ledger-status`: `N in the live view` or `N matching`, `N hidden by type`, `Request N selected` and a small × (`#ledgerClearSelection`, `Clear the selection`, which clears it and closes the drawer like Esc); the bar has no hint text). Only the rows in view are in the DOM.

**Querying.** Whenever Marasi reads fresh results from the top (a typed or menu-toggled query such as a Highlights or Marks row, a sort, Live, an exclusion change), the store's `querying` is true: the toolbar's search icon becomes a spinner (`.ledger-querying`, `title="Querying Marasi…"`; it also spins while a typed query waits out its delay), and once the read has taken 150 ms (at once while the table has no rows, including before the project's first read starts) the table (`aria-busy="true"`) swaps its rows for pulsing ghost rows (`.ledger-ghost`, bars `.ledger-ghost-bar`) under the header, and while the sitemap's first level reads it shows ghost hosts (`.ledger-sitemap-ghost`; an expanding node shows one ghost line). A query doesn't ghost the sitemap: its tree stays and its counts update, while `#ledgerCount` reads `Querying Marasi…` and `#ledgerQueryMatchCount` `Querying…`. Local reads finish too fast to see; to capture it, temporarily delay `api.queryTraffic` in `readFirstPage` and revert. Paging while scrolling, jumps and rows read again in place show no ghost.

**Background-job notices.** While a query runs and Marasi's search index is still building, `#ledgerIndexBuilding` (`Search index still building`) sits beside the match count. While the `prettified_move` job runs, the drawer's Prettify button (rail) and Pretty row (column) carry an amber dot, `.ledger-drawer-indexing`, and their tooltip adds `Indexing data: some bodies may not show prettified yet`. Both clear without a reload: the app polls `ListJobs` every 2s while a job runs, then reads the Ledger again in place (the sitemap reloads when its job finishes). To see them, rebuild from Settings → Maintenance with enough traffic captured.

The sitemap dock (`.ledger-sitemap`) has a header with `Sitemap` and the host count (`.ledger-sitemap-hosts`, `N hosts`), `Sitemap still building` (`.ledger-sitemap-building`) while Marasi's sitemap job runs, the find box `.ledger-sitemap-find` (filters the loaded hosts and paths; Escape or a click elsewhere leaves it and keeps the text, its × clears it), `Collapse all` (`.ledger-sitemap-collapse-all`) and the scope toggle (`.ledger-sitemap-scope`: square, borderless segments `All` and `Matching` (the chosen one in the primary button variant: ghost in light, filled in dark), the second disabled without a running query). `#ledgerLive` in the toolbar, before Saved queries, reads `Live`: a `span` with a green dot while the table is the live view (no query typed or running, newest first), and a `button` with a grey dot otherwise. Clicking it empties the query (so marks, highlights, sitemap nodes and saved queries go too), restores newest first and reads from the top. Scrollbars are thin everywhere (one global rule in `app.css`). Rows are `.ledger-sitemap-node[data-sitemap-node="<node name>"]`: an expand chevron (`aria-label` `Expand <name>`/`Collapse <name>`), the segment (placeholders `{uuid}`, `{int}`, `{hash}` in italics; clicking narrows the query to `sitemap = "<name>"`, again removes it, and the active node has `aria-current="true"`), an eye button (`.ledger-sitemap-hide`) that toggles `sitemap != "<name>"`: on hover it shows an eye-off (`aria-label` `Leave <name> out of the query`) and adds the term; while the query has it, it stays shown as a primary open eye (`aria-pressed="true"`, `aria-label` `Show <name> again`) and a click removes it; clicking the hidden node's name shows it again too, the 5xx count and the pair count (`matching/total` in All traffic with a query; nodes without matches are dimmed). When the query, its as_of, the exclusion or the scope changes, every open level is read again: until its read lands, its rows' counts are faded and pulsing (`.ledger-sitemap-stale`, title `Updating for the current query…`) rather than passing for the new answer. One `ListSitemapLevels` call reads every open level (up to 64 per call), so Marasi resolves the query once for all of them; a newer change's answer wins. On the 100k fixture, four levels under `status_code >= 500` with the default 80-type exclusion take about 80 ms through the app (64 ms in Matching), and the dock settles within half a second of a query or scope change; before Marasi 875b813 and d343159 it was 1.5–2 s per level, and 7.8 s per call with the exclusion. Check exactness with `CountTraffic('(q) AND sitemap = "<child>"', "", { AsOf })` against each child's `Matching` (All) or `Pairs` (Matching). Opening a node and "Show more" still read one level through `ListSitemapChildren`. Each level shows its busiest 10 children, then `.ledger-sitemap-more` (`N more` with `Show 50 more`). The strip's search button, or `cmd+shift+\` with the drawer open or closed, expands the dock and focuses the find box; `cmd+shift+\` again leaves it.

Shortcuts: every menu shortcut for this feature is a catalog action in context `ledger.drawer-closed`, `ledger.drawer-open` and `ledger.drawer-open.websocket` (and, in the WebSocket modal, `websocket` plus `websocket.<tab>`) in `frontend/src/lib/keybindings/catalog.js`; the Marasi menu (`⌘K`) on the page lists them with their current keys. The drawer contexts follow the Ledger store's drawer (`state.ledgerDrawer` in the layout's shortcut state), not Skeleton's drawer.

## Performance budget

The app loads the Ledger's code once the project is open (`preloadCode("/ledger")` in `+layout.svelte`), so the first visit doesn't wait for it, and the project's first Ledger read is sent before extensions load. Hold every Ledger change to this budget, measured on an 85,000-request (about 1 GB) project:

| Figure | Budget (ms) | Measured 2026-10-17 | What it times |
| --- | --- | --- | --- |
| `firstVisit` | 150 | 64–67 (532–551 before the preload) | Home → Ledger click to the toolbar painting, the first visit after launch |
| `startupRows` | 500 | 58 by the bench's poll; 226–259 when clicked the instant Home paints (1.4–5.5 s before Marasi's `DashboardCounts`) | Reload, then Ledger clicked as soon as Home shows, to the first row |
| `warmShell`, `warmRows` | 100 | 35–36, 35–36 | Home → Ledger click to the toolbar and the first row, later visits |
| `longestTask` | 100 | 0 (no task over 50 ms) | Longest main-thread task during a visit |
| `sortRows` | 300 | 23–26 | A sort header click to the newly sorted first row (a full first-page read) |
| `firstPage` | 50 | 6–7 | Marasi's QueryTraffic for the live view's first page, alone |
| `count` | none | 122–124 | Marasi's CountTraffic for the live view; it grows with the project and is reported, not budgeted |

Run it:

1. `scripts/launch.sh`, then `scripts/bench-seed.sh` (85,000 requests by default; about 15 minutes; it runs `bench-server.py` on 127.0.0.1:18999 for the upstream).
2. `scripts/bench-ledger.sh`. It restarts the instance (the project is kept) so `firstVisit` loads the code as a user's first visit does, prints each figure against its budget, writes `<evidence>/bench-ledger.json`, and exits 1 when one is over.

Figures come from headless Chrome against the dev server, so they compare runs on one machine, not the WebKit app. Marasi answers one call at a time: anything the Ledger asks for waits behind whatever else is in flight (on a fresh launch, the dashboard's `CountNotes`, about 1.6 s on this project), so measure with the app idle. Since Marasi v0.0.0-20261016190652-f338aa018cfb the dashboard's `CountNotes` is one `DashboardCounts` read (11 ms at 85,000 requests, from 1.6 s), so a fresh launch's first Ledger page arrives about 940 ms after start rather than 2.5 s. On a project's first open after an upgrade, Marasi's background jobs can still hold calls up for about 250 ms each for some 27 s; don't benchmark then.

## Driving it with Chrome CDP

Run `scripts/drive.sh ledger` for route proof; it waits for the toolbar's `Saved queries`, which paints whether the dock is open or collapsed. For capture, send a `text/html` request with a unique path through the isolated proxy (`curl -x http://127.0.0.1:18080 …` to a local disposable server), then wait for that path in the table:

```bash
scripts/drive.sh ledger steps '{"name":"capture","steps":[{"waitText":"/ledger-second"}]}'
```

Pair it with a read-only query: `sqlite3 -readonly <project> "select method, host, path, status_code, content_type from request"`.

Search supports field expressions and boolean operators, not just a table substring filter. A proven sequence:

```json
{"name":"search","steps":[
 {"click":"#searchBox"},{"key":"cmd+a"},
 {"insert":"response_body:\"ledger-second\""},{"key":"enter"},
 {"waitSelector":"#ledgerQueryMatchCount"},{"waitText":"1 match"},{"waitText":"1 matching"},
 {"waitNoText":"/ledger-first"},{"waitText":"/ledger-second"},
 {"click":"[aria-label=\"Clear query\"]"},{"waitText":"/ledger-first"}]}
```

The query stays active across navigation until cleared, so the recipe clears it; otherwise later recipes cannot find rows the query excludes.

Enter runs the query at once. Typing alone runs it after a 700 ms debounce. `#ledgerQueryMatchCount` reads `1 match`, `N matches`, or `N+ matches` while older pages remain. The query-help toggle describes the supported fields, operators, and examples.

The query box is a one-line CodeMirror editor; `#searchBox` is its `.cm-content`, so `click`, `cmd+a` and `insert` work as on an input. It offers suggestions in `.cm-tooltip-autocomplete`: fields by prefix while typing a word (including `highlight`, `sitemap`, `finding`, `test_case`, `length` and `metadata.`), a field's operators after `<field> `, and example values after the operator (`*` after `highlight:`, `note:`, `launchpad:`, `finding:`, `test_case:` and `metadata.<key>:`). `Ctrl-Space` opens them on request. Enter picks the selected suggestion while the list is open and runs the query otherwise; a finished value or word offers nothing, so Enter after an inserted query runs it. Pick with `{"click":".cm-tooltip-autocomplete li","hasText":"<label>"}` or `down` and `enter`. Escape leaves the box at once, closing an open list (focus goes back to the page; the query stays; `#ledgerQueryClear` clears it). A click anywhere outside the box leaves it too, rows included. Leaving it (or a drawer editor) clears the DOM selection inside it too: WebKit, unlike Chrome, keeps a blurred editor's selection and goes on drawing its caret, so check with `getSelection().rangeCount` and whether `#searchBox` contains its anchor, in Playwright WebKit as well as Chrome. When the query runs past the box, `#ledgerQueryExpand` (`Show the whole query`, `aria-pressed`) wraps it onto as many lines as it needs, the toolbar growing up to 30vh before the box scrolls; pressing it again (`Back to one line`) returns to one line. An invalid query shows its message in `#ledgerQueryError` (`role="alert"`) in place of the match count and underlines the word at Marasi's position (`.ledger-query-error`). Bare text searches the request, response, note, and metadata, and needs at least three characters; punctuation can require quoting.

For handoff, click a row with `{"click":".ledger-row","hasText":"<path>"}`, wait for `.ledger-drawer` (below the table, request and response side by side), then use the drawer's shortcuts. For example, `cmd+shift+l` sends the selection to a new launchpad and shows `Sent 1 request to a new launchpad` (`Sent N requests …` for several; the launchpad is named `Request N` or `N requests`) with a `Jump to Launchpad` action. `cmd+shift+e` maximises the drawer over the table (`.ledger-table` leaves the DOM) and restores it; `cmd+shift+]`/`[` open the request with the next or previous number, whether the results hold it or not (a loaded one is selected in the table; with the drawer on request 1000 opened by `cmd+shift+o` outside a query, `cmd+shift+]` opens 1001); `cmd+]`/`[` open the results' highest- or lowest-numbered request (under a `#` sort that is the table's top or bottom row, its page read into the table when it isn't loaded; under another sort it is selected where loaded and opens on its own otherwise); `escape`, the status bar's `Clear`, or the drawer's `Close the drawer` button closes it. Drag `.ledger-drawer-resize` to resize it: `{"drag":".ledger-drawer-resize","to":".ledger-row","toHasText":"<path near the top>"}` (prove it with the drawer's height before and after). The selection, the drawer's height and maximised state, and the dock's width and collapsed state survive leaving and returning to the Ledger, so close the drawer at the end of a recipe.

**The drawer.** `.ledger-drawer` is the request (`.ledger-drawer-request`) and the response (`.ledger-drawer-response`) side by side in CodeMirror at 11px, like the table's rows and the details column, unlabelled and flush against the drawer's red top line (`.ledger-drawer-edge`, a 1px overlay above the drawer's content in its own stacking context, so a scrolled or bouncing editor can't paint over it; the resize handle `.ledger-drawer-resize` overlays it and takes no room; the editors don't scroll the page or bounce past their edges; `Waiting for the response…` until a response arrives), with a 3px `.ledger-drawer-highlight` stripe on its left edge when the pair is highlighted. There is no button ribbon. On its left sits the rail, `.ledger-drawer-rail` (collapsed, the default), or the 15rem details column, `.ledger-drawer-column`; `.ledger-drawer-expand` (`Show the details` / `Collapse the details`, `aria-expanded`) switches them, and the Ledger store keeps the choice (`layout.drawer.expanded`) across closing the drawer, other pairs and page visits, in memory only. Both carry the buttons `Previous request`, `Next request`, `Maximise the drawer`/`Restore the table` and `Close the drawer` (aria-labels; titles add the current shortcut). The rail lists, by aria-label, `Open WebSocket stream` (upgrade rows only), `Copy request`, `Copy response`, `Copy URL`, `Copy browser view URL`, `Send to Launchpad`, `Send to Armory`, `Create finding`, `Create test case`, `Note` (`data-status` `saved`/`unsaved`/`saving`/`failed`; its dot is neutral grey when the pair has a note, amber while an edit is unsaved or saving, red after a failed save), `Metadata`, `Prettify` and `Wrap lines` (both `aria-pressed`); its action list scrolls when the drawer is short, fading out over 16px at whichever edge cuts an action off (`data-fade` reads `top`, `bottom`, both, or nothing). Rail and column use the rows' surface (`bg-surface-50`/`dark:bg-surface-900`). The column shows `#N`, the facts (`.ledger-drawer-facts`: method, status, timing, host and path on one truncated line, `.ledger-drawer-url`, whose `title` is the whole URL, content type · size), the highlight swatches (`.ledger-drawer-swatches`, `[data-highlight=<n>]`, `role=radio`; a click toasts like the row menu's swatches, `Highlighted 1 request "Orange"`, and clicking the current one clears it), a read-only note preview (`.ledger-drawer-note-preview`, three lines; `.ledger-drawer-note-edit` reads `Add` or `Edit`), Linked findings and test cases, the actions as labelled buttons with their shortcuts (click them with `{"click":".ledger-drawer-column button","hasText":"Copy request"}`: the shortcut is part of their text), and the View checkboxes `Pretty` and `Wrap lines`. Every action runs the same handler as its shortcut, with the same toasts (`Request copied to clipboard`, `Copied URL`).

**Long strings.** The drawer's editors fold every run of 10,000+ characters without a space, quote, angle bracket, `=`, `&` or `,` into a `.cm-long-string` placeholder (`… 2.4 MB · show`); a press shows the string. Under the Auto Line wrapping setting (settings.md), once a shown line is over 100,000 characters the rail's `Wrap lines` button gets an amber dot (`.ledger-drawer-wrap-suspended`) and that body stops wrapping; under Enabled it wraps anyway, and under Disabled `Wrap lines` starts unpressed. Proven against a JSON response holding a 2.5 MB base64 string: `{"click":".ledger-row","hasText":"/bigjson"},{"waitSelector":".ledger-drawer-response .cm-long-string"},{"waitNoSelector":".ledger-drawer-wrap-suspended"},{"click":".ledger-drawer-response .cm-long-string"},{"waitNoSelector":".ledger-drawer-response .cm-long-string"},{"waitSelector":".ledger-drawer-wrap-suspended"},{"key":"escape"}`.

The note (rail `Note`, column `Add`/`Edit` or the preview, `⌘⇧N`, or the row menu's `Add note…`/`Edit note…`) opens in place of the response as `.ledger-drawer-note` (`data-status` as on the rail button): just a wrapping CodeMirror editor, no header; the pressed rail `Note` button is the only sign it is open (click `.ledger-drawer-note .cm-content`, then `insert`). While the note is open, the column's Note heading (`.ledger-drawer-note-heading`, `data-status`) follows the rail dot (undimmed when saved, amber while unsaved or saving, red after a failed save) and adds `.ledger-note-status` (`Edited`, `Saving…`, `Not saved`) when it isn't saved. After a failed save, the next edit or closing the note tries again. Edits save about 0.6 s after typing stops, and whatever is unsaved saves when the pane closes or the drawer moves to another pair; prove it with `sqlite3 <project> "select * from notes"`. `⌘⇧N` again (from inside the editor too) goes back to the response; the pane stays open while `cmd+shift+]`/`[` step through the requests, showing each pair's note. `⌘⇧M` (rail `Metadata`, the row menu's `metadata`) opens the metadata the same way, with no header, as read-only JSON in `.ledger-drawer-metadata`; the pressed `Metadata` button (or `⌘⇧M`) goes back. Several selected pairs' `Append a note…` and `Clear notes…` keep their modals.

**A refused ⌘A change.** Marasi refuses a bulk change on a ⌘A (query) selection while a job its query depends on is building, and changes nothing: a text term waits on the search index (`traffic_index`, `annotation_index`), a `sitemap` condition on the sitemap; listed ids are never refused. The app reports it as `selection_incomplete (<jobs>)` in the error, and the Ledger shows a warning toast, `Failed to … : Marasi is still building its search index, so nothing changed. Try again once it finishes.`, with `Retry`; a refused new launchpad is deleted again rather than left empty. To see it, open the 100k fixture, rebuild the search index from Settings › Maintenance (well over 30 minutes there), run a bare-word query such as `item`, press ⌘A and highlight; a query with no text term, such as `host = "…"`, still applies. The ⌘A delete confirmation says `all N requests that match now`: a selection reaches the pairs captured up to its as_of as they are when it runs.

**Selection and the row menu.** Pressing a row selects it alone; dragging across rows sweeps them; `⌘`-click toggles, `⇧`-click selects from the anchor, `⌘⇧`-click adds that range. Drive them with `"modifiers"` on a click (`{"click":".ledger-row","hasText":"/b","modifiers":["shift"]}`, `["cmd"]`) and the sweep with a `drag` step (`{"drag":".ledger-row","hasText":"/a","to":".ledger-row","toHasText":"/c"}`). With the table focused, `⇧↓`/`⇧↑` extend from the anchor (the driver sends `shift+down` and `shift+up`), `cmd+a` selects the whole query or live view as a Marasi selection (query, exclusion and the results' as_of, never ids; every loaded row up to that as_of shows selected, later new matches do not), and `escape` clears. Selected rows carry `aria-selected="true"`; the focused one, which the drawer shows, is outlined. The status bar reads `Request N selected`, `N selected`, or after `cmd+a` `All N matching selected`, plus ` · M new matches not included` once new matches arrive (`#ledgerSelectionCount`). Right-click a row (`{"click":".ledger-row","hasText":"<path>","button":"right"}`; on a selected row the menu acts on the selection, on any other row on that row alone, and either way the selection, the focus and the drawer stay as they were, so a closed drawer stays closed) or press `cmd+shift+.` to open `.ledger-row-menu`: a header summing up what it acts on, a `Type an action…` filter (`.ledger-row-menu-filter`, which searches submenus too), then items `[data-menu-item=<id>]` (`websocket`, `launchpad`, `armory`, `browser-view`, `finding`, `testcase`, `note`, `highlight`, `copy`, `narrow`, `select`, `metadata`, `delete`). Submenus nest, one group each, with no headings: `launchpad` holds `lp-new`, `lp-each` (several pairs), `lp-add` (Add to launchpad ›, the launchpads as `lp-<id>`; disabled `No launchpads yet` without any) and `lp-remove` (Remove from launchpad ›, `lpu-<id>`); `finding` and `testcase` hold `f-new`/`t-new`, `f-link`/`t-link` (Link to … ›, `f-<id>` with check states) and, when something is linked, `f-unlink`/`t-unlink` (`fu-<id>`/`tu-<id>`); `narrow` ends with `q-hide` (Hide type ›, `x-<type>`). Hover each level in turn (`{"hover":"[data-menu-item=launchpad]"},{"hover":"[data-menu-item=lp-add]"},{"click":"[data-menu-item=lp-<id>]"}`). With several pairs the labels name the count: `3 URLs`, `3 requests as cURL commands`, `3 raw requests`, `3 requests as a Markdown table`, `3 request numbers`. With several pairs, `note` is a submenu: `n-append` (`Append a note…`, a prompt modal) and `n-clear` (`Clear notes…`). `delete` (`Delete from project…` / `Delete N from project…`) and `n-clear` open the confirm modal naming the count (Delete warns `… evidence in a finding.` when any pair is); nothing changes until it is confirmed. After `cmd+a` over more rows than are loaded, `armory`, `copy`, `lp-each`, `f-new` and `t-new` are disabled (`Not for all matching`), their shortcuts (`⌘⇧A`, `⌘⇧F`, `⌘⇧T`, the copy keys) only toast `Not for all matching`, and the header reads `All N matching` without the host, method and status breakdown. `select` lists `s-highlight-<n>` for each highlight among the selected pairs (`All with this highlight`, or `All with highlight <label>` when there are several). Items that would change nothing for the loaded selection are disabled with their reason as the hint (a swatch every selected pair already has: `Already highlighted`; `h-none` with nothing highlighted: `Nothing to clear`; `n-clear` with no notes: `No notes to clear`; a finding or test case every pair is linked to: `Already linked`); a disabled swatch has `aria-disabled="true"` and its reason shows at the row's end on hover. Under a partly loaded ⌘A selection nothing is disabled for this. Marasi refuses to delete a pair whose Launchpad launch is still pending, or to remove it from the launchpad it was launched from (marasi `docs/adr/2026-10-18-a-pending-launchs-pair-stays-in-its-launchpad.md`), so for such a pair `delete` and that launchpad's `lpu-<id>` are disabled with `N launching` (other launchpads' `lpu-<id>` stay enabled). A ⌘A selection whose pairs are all loaded is greyed the same way; a partly loaded one stays enabled and, on Marasi's `launch_pending` refusal, toasts `N pairs are still launching; nothing was deleted` (or `…removed`) and selects the refused rows. Proven with a launch kept pending by a slow origin (see `launchpad.md`): `{"click":".ledger-row","hasText":"/slow?sleep=600","button":"right"},{"hover":"[data-menu-item=launchpad]"},{"hover":"[data-menu-item=lp-remove]"}`, then read `title="1 launching"` on `[data-menu-item=delete]` and the launched-from `lpu-<id>`. Bulk changes run once on the selection and toast Marasi's count, and say nothing when Marasi changed no pair of a listed selection (removing from a launchpad they aren't in, say); after ⌘A, whose pairs aren't all loaded, they say why instead (`None of the 1,200 matching requests had a highlight`, `All 3 matching requests were already in "Login"`, `The matching request had no note`) (`Added 3 requests to "…"`, `Removed 1 request from "…"`, `Appended a note to 2 requests`, `Cleared 2 notes`, `Deleted 2 requests`); the rows are read again in place. The `highlight` item is a row of swatches (`.ledger-highlight-swatches`, buttons `[data-menu-item=h-1]` to `h-8` and `h-none`, `role=menuitemradio`, `aria-checked` `true`/`mixed`/`false`); hovering one shows its label at the row's end, and with the row active `arrowleft`/`arrowright` pick a swatch and `enter` applies it. Typing a label in the filter lists the swatch as `Highlight › <label>`. Applying one toasts Marasi's count (`Highlighted 2 requests "Red"`, `Cleared the highlight on 1 request`) and repaints the rows' 3px stripe and tint in place. Submenus open in `.ledger-row-submenu[data-menu-level="<n>"]`, flush against their parent with their first item level with the parent item, running up instead (last item level) when they don't fit below. A first-level submenu opens on the side with room for every level below it, and deeper levels keep that side; the menu itself opens above the pointer near the bottom and left of it near the right edge. The placement rules are unit-tested in `menuPlacement.test.js`. Keys: arrows move, `arrowright`/`enter` open a submenu, `arrowleft` goes back, `enter` runs, `escape` closes the deepest submenu first (so a reset may need two). The driver has no `right` key: use `enter` to open a submenu. Each change reports through a toast (`Linked 2 requests to finding "…"` with the count Marasi changed, `Selected N requests`, `Narrowed the query: …`, `Copied 2 URLs`). `browser-view` (`Copy browser view URL`, also on the drawer's rail and column and `⌘⇧V` with the drawer open, which yields to a focused editor) copies `http://marasi/view/<uuid>` and toasts `Copied the browser view URL. Open it in a browser that uses Marasi's proxy`; it is disabled for several pairs (`One request at a time`), a pair without a response (`No response yet`) and a WebSocket upgrade (`Not for a WebSocket upgrade`). What the URL serves is in `launchpad.md`. Proven: `{"click":".ledger-row","hasText":"/compass-allowed.html","button":"right"},{"click":"[data-menu-item=browser-view]"},{"waitText":"browser view URL","within":".snackbar-wrapper"}`, and with the drawer open on a row `{"key":"cmd+shift+v"}` with the same toast. Shortcuts with a selection: `⌘⇧L` new launchpad, `⌘⇧A` Armory, `⌘⇧F` new finding, `⌘⇧T` new test case, `⌘⇧N` note, `⌘⇧C` copy URLs, `⌘⇧M` metadata, `⌘⇧.` the menu (`⌘.` stays Jump to Toast and `⌘L` Setup Listener).

## WebSocket streams

A WebSocket message is the whole message, however many frames it arrived in. UI text says "message"; action ids keep `frame` (`websocket.stream.next-frame`, `websocket.checkpoint.forward-frame`, `websocket.inject.inject-frame`).

Drive a WebSocket through the proxy with a raw-socket client: send an absolute-form upgrade (`GET http://127.0.0.1:<port>/<path> HTTP/1.1` with `Upgrade: websocket`, `Connection: Upgrade`, `Sec-WebSocket-Key`, `Sec-WebSocket-Version: 13`) to `127.0.0.1:18080`, then read and write masked frames. Use a disposable local server you control, so each state below is a deliberate server behaviour. Offer `Sec-WebSocket-Extensions: permessage-deflate` to get a deflate connection; add another offer (for example `x-webkit-deflate-frame`) to see it stripped.

**Upgrade states.** The badges column shows a WebSocket icon (its label is the badge's `title` and `aria-label`; past three badges, hover the `+N` slot `.ledger-badges-more` for the full list) whose state comes from `frontend/src/lib/websocket/presentation.js`:

| `websocket.state` | Icon | Opens a stream | How to produce it |
| --- | --- | --- | --- |
| `pending` | warning | yes | Hold the server's 101 response |
| `open` | success | yes | Complete the handshake |
| `closed` (or no state) | error | yes | Close the connection from either side |
| `failed` | error, slashed; tooltip `WebSocket handshake failed — see the logs on Home` | no | Offer `permessage-deflate` and have the server answer an extension response that matches no offer (for example `permessage-deflate; server_max_window_bits=20`, or two extensions). Home's logs get `WebSocket handshake failed: …` |
| `dropped` | neutral, slashed; tooltip `Upgrade response dropped` | no | Drop the 101 response in Checkpoint (see [checkpoint.md](checkpoint.md)) |

A failed or dropped upgrade reaches the Ledger live through `ws-state`, with no reload. A slashed row has no drawer `Open WebSocket stream` button, and `ledger.drawer-open.websocket` is ineligible, so `⌘⇧G` does nothing there (`⌘⇧O` is Open request in every Ledger state). Prove the tooltip with `[title="Upgrade response dropped"]` or the failed text.

**Opening the modal.** Open the upgrade row's drawer and click `Open WebSocket stream` in its rail or details column, or press `Open WebSocket Stream` (`⌘⇧G`; it closes the modal again from every tab, Inject included, whose `⌘⇧O` cycles the opcode). The header shows `<transport>://<host><path>`, `N messages`, and `Close Connection` (`⌘⇧X`, toast `WebSocket connection closed`, disabled unless the state is open). Tabs, in `⌘[`/`⌘]` order: `Stream`, `Checkpoint`, `Inject`, `Connection`. Each tab's context is `websocket.stream`, `websocket.checkpoint`, `websocket.inject`, or `websocket.connection`; the Connection tab binds no actions of its own.

**Progress chip.** While a message is still arriving, the header shows `↓ receiving <size> · <n> frames` (`↑` for client to server), titled `A message is still arriving; it appears in Stream once its last frame is in`. Produce it with a fragmented message whose frames arrive more than 100 ms apart (Marasi emits progress at most every 100 ms): send a text frame with FIN clear, then continuations a second apart, then the final frame. The chip clears when the message lands in Stream, or when Checkpoint holds it.

**Stream.** Selecting a row shows the properties grid above the payload: `Type`, `Direction` (`client → server`/`server → client`, plus `(sent by Marasi)` on Marasi's own closes), `Size`, `Frames`, `Compressed` (`yes`/`no`), `Flags`, and a `Note` when the payload shown is not the message. Buttons: `Metadata`/`View Message` (`⌘⇧M`) and `Copy to Inject` (`⌘⇧I`, toast `Copied to Inject`). Flags, their row edge, and how to produce them:

| Flag | Edge | Produce it |
| --- | --- | --- |
| `Proxy` | warning | Any close Marasi sends, for example after `Too large` |
| `Too large` | error | Add `websocket_max_message_size: 1024` to `marasi_config.yaml` in the isolated config directory, run `scripts/restart.sh`, then send a 2 KB message. Marasi closes with 1009 to the sender and 1001 to the receiver; `Size` reads `> <size seen>` |
| `Corrupt` | error | On a deflate connection, send an RSV1 frame whose payload is not valid deflate (close 1007) |
| `Cut short` | error | Start a fragmented message and drop the TCP connection before its final frame |
| `Bad close` | error | Send a close frame with an invalid code or a 1-byte payload |
| `Dropped` | strike-through, no edge | Drop it in the Checkpoint tab |
| `Injected` | tertiary text | Inject it from the Inject tab |

Hover a row to read `<label>: <flag tooltip>` lines; a forwarded interception reads `Forwarded intercepted message`.

**Inject.** `Direction` (`Client to server`/`Server to client`, `⌘⇧D`), `Opcode` (`Text`, `Binary`, `Close`, `Ping`, `Pong`, `⌘⇧O`), and `Inject` (`⌘⇧Enter`, toast `WebSocket message injected`) beside a `Connection Open`/`Connection Closed` chip. On a deflate connection with `Text` or `Binary`, a `Send uncompressed` checkbox appears under the toolbar. Prove both choices: inject once with it clear and once checked, then check the injected rows' `Compressed` reads `yes` and `no`.

**Connection.** Read-only: `URL`, `State` chip, `Close` (`<code> <reason>`, with `— closed by Marasi` in warning colour when any stored message is a Marasi close), a `Compression` section (`Extension` `permessage-deflate` with client/server context takeover and max window rows, `none negotiated`, or `not recorded` without a connection record), and `Stripped by Marasi` with one `Offer` row per stripped extension or `none`.

## Gotchas

- `#searchBox` is always in the toolbar. The Types menu mounts only while open: open it with `{"click":"#ledgerTypesButton"}` (its text includes the hidden badge, so `{"text":"Types"}` fails) or `⌘F` (drawer open or closed), which also focuses `#ledgerTypesFind`; typing a full type or `major/*` there and pressing Enter (or clicking `#ledgerTypesAdd`) hides it. A click outside the menu closes it (click `.ledger-status`, not the table, which would select a row); Esc closes it only while focus is inside the menu, so after clicking a row in it, close it with a click on `.ledger-status`. This holds for every toolbar menu. `⌘P` toggles the query fields panel; `⌘S` focuses `#searchBox` (pressing it again blurs the box), with the drawer open or closed. Settings is `⌘,` (Copy Certificate `⌘⇧,`). `⌘]`/`⌘[` scroll the table a page.
- The `Saved queries` menu (`{"click":"#ledgerSavedQueriesButton"}`; its badge is the active saved query's name) opens `#ledgerSavedQueriesPanel` with groups `This project`, `All projects` and `Built-in` (the six built-ins from the spec; empty groups are left out) of `.ledger-saved-query` rows, each with a match count read with `CountTraffic` after the panel opens (`…` while loading, `!` for a query Marasi rejects). Click a row's name to replace the query in `#searchBox` and run it; clicking the active one clears it. `#ledgerSaveQuery` (`Save current query`) is enabled only for a valid, already-run query no visible saved query has; it shows `#ledgerSavedQueryName`, the checkbox `#ledgerSavedQueryKeepForAll` (`Keep for all projects`, off by default: the query goes to `This project`) and Save. Hovering a row shows `button[aria-label="Rename <name>"]`, `button[aria-label="Delete <name>"]` (confirm modal; a project query's reads `from this project`) and `button[aria-label="Move <name> to all projects"]` or `button[aria-label="Move <name> to this project"]` for saved queries, or `button[aria-label="Hide <name>"]` for built-ins; `#ledgerShowHiddenBuiltins` (`Show N hidden built-ins`) lists hidden ones with `Show <name>`. A query equal to a hidden built-in still badges its name and can't be saved again. Changes show at once and are put back, with an error toast, if the write fails. App-wide queries persist to `saved_queries` and hidden ids to `hidden_builtin_queries` in `marasi_appconfig.yaml`; prove persistence with `restart.sh`. Project queries are rows in the project file: `sqlite3 -readonly <project> "select key, value from client_setting where client = 'marasi-app' and key like 'ledger.saved_query.%'"`; a move leaves exactly one copy across the YAML and that table.
- The `Marks` menu (`{"click":"#ledgerMarksButton"}`; its text includes the active-mark badge) opens `#ledgerMarksPanel` with one `.ledger-mark` row per mark, each with a `data-term` (`note:*`, `finding:*`, `test_case:*`, `launchpad:*`, `metadata.intercepted = true`) and a `.ledger-mark-count` read with `CountTraffic` on each opening (`…` while loading, `–` on failure). Click a row (`{"click":".ledger-mark","hasText":"Has note"}`) to toggle its term in `#searchBox` and run the query at once; the panel stays open and the row gets `aria-checked="true"`. Esc or a click outside closes it.
- The `Highlights` menu (`{"click":"#ledgerHighlightsButton"}`; badge = highlight terms in the query) opens `#ledgerHighlightsPanel`: `Any highlight` (`highlight:*`) and one `.ledger-highlight` row per highlight (`data-term` `highlight = N`) with swatch, label, scope tag (`project`/`app`) and `.ledger-highlight-count`. Clicking a highlight row toggles its term like Marks, 250 ms after the click so a double-click only renames. The pencil (`.ledger-highlight-rename-button`, shown on hover) or a double-click opens `.ledger-highlight-rename` with a label input and a `Use in all projects` checkbox; Enter saves (unticked: the project's `ledger.highlight.<n>`; ticked: the app label, dropping the project's), Esc cancels.
- On project open, a project with old hex highlights (`metadata.highlight`) is migrated once in the background; the toolbar shows `#ledgerHighlightMigration` (`Updating old highlights…`) meanwhile, then the table reloads. The project's client setting `ledger.highlight_migrated` records it. Marasi has one database connection, so the migration and the project's other opening reads queue behind each other: on the 100k fixture it finished while the page still showed `Loading <project>…` (about 50 s), and the notice never painted. Prove the migration in SQLite instead: `ledger.highlight_migrated` is `true`, `select count(*) from request where json_extract(metadata,'$.highlight') is not null` is 0, and `pair_highlight` holds each mapped number (`#EF4444`→1, `#EAB308`→3, `#22C55E`→4, `#3B82F6`→6, `#A855F7`→7; a pair that already had a number keeps it). Open an APFS clone (`cp -c`) of the fixture for each attempt: the flag makes later opens skip it.
- Clicking anywhere in `.ledger-table` selects the row under the pointer and opens the drawer, which swaps the shortcut context to `ledger.drawer-open` (`⌘⇧F` then creates a finding).
- The content-type exclusion hides matching types. The app default (Settings → Content Types, table `#settingsDefaultContentTypes`) already hides images, fonts, media, JavaScript, CSS, PDF, archives, and office types. Use `text/html` for capture proof. They include `application/octet-stream`, which `python3 -m http.server` sends for extensionless paths, so serve a `.html` path.
- An empty Ledger only proves navigation. Complete capture proof needs traffic through the proxy.
- HTTPS traffic needs the verification instance's generated certificate.
- Search and filters can hide newly captured rows; record their values in evidence.
- The live view batches `request`/`response` events and flushes every 200 ms. The table lists the live view and query results newest first by default. Every header but badges sorts: `button[data-sort="<field>"][title="Sort by …"]` (`#` sorts by `number`, `Time` by `requested_at`); a click sorts, a second reverses, and the sorted header has `aria-sort` `ascending`/`descending`. It also shows an arrow and turns primary, except in the default sort (`number desc`, newest first), where no header is marked and `#` keeps `aria-sort="descending"` with the title `Newest first · click for oldest first`; `#` sorted oldest first shows `#↑`. Pairs without a response sort last both ways and show `…` dimmed in Status (Marasi stores status `-1` for them). In the newest-first live view new traffic lands on top; scrolled down, the rows stay put and a `N new` button returns to the top. During a query (or any other sort) matching traffic waits behind `1 new match · Show` or `N new matches · Show`, which appears once traffic pauses for 500 ms (at most 3 s after the first new pair under steady traffic); `Show` reads the results again in place. A `cmd+a` selection then reads `All N matching selected · M new matches not included`.
- An exclusion value is an exact type or a whole major type (`image/*`); the Images, Fonts, Audio and Video chips store `major/*`. A type hidden through `major/*` has a disabled checkbox. Inspect the Types menu rather than assuming defaults: editing it gives the project its own list, which no longer follows Settings.
- Replacing the query text: `cmd+a` right after clicking `#searchBox` sometimes loses to the click's caret, so `insert` appends. Clear first with `{"click":"[aria-label=\"Clear query\"]"}`, or press `escape` twice in the box (close suggestions, then clear), then click and insert.
- Saved queries: the row actions (Rename, Move, Delete, Hide, and `Show <name>` in the hidden list) only show on hover; reach them with a `hover` step on the row first (`{"hover":".ledger-saved-query","hasText":"<name>"}`). A rename commits on Enter. Delete's confirm button is `Confirm`; the Types menu's `Reset to default` confirm is `Confirm` too.
- Highlights menu: rename with `{"hover":".ledger-highlight","hasText":"<label>"}` then the pencil, or `{"click":".ledger-highlight button[title=\"highlight = N\"]","clickCount":2}`. The input is `input[aria-label="Label for highlight N"]`; save with `.ledger-highlight-rename button[aria-label=Save]` (Enter after an `insert` did not always submit) and tick `.ledger-highlight-rename input[type=checkbox]` for `Use in all projects`.
- Sitemap: `button[aria-label="Expand <node>"]` opens a node (origins are `https://host`); a node's own button has `title="Narrow the query to sitemap = …"`. The strip's buttons are `button[title="Show the sitemap"]` and `button[title="Search the sitemap"]`. In `Matching`, open levels read again one by one: wait until a child's All-traffic total (for example `4,654`) is gone before a screenshot. `Sitemap still building` reflects the last sitemap read, so after a Rebuild it shows on the next read (switch scope or change the query), not by itself.
- Large-project timing (100k fixture, Apple M2): the first rows paint at once; Matching-mode reads and saved-query counts take 1–5 s; rebuilding the search index takes over 30 minutes for `traffic_index` alone, and while it runs text queries match nothing yet (`0 matching` with `Search index still building`). Rebuild the sitemap (about 1 minute) rather than the index when you only need a notice.
- Delete confirmation: the modal names the count and, when any pair is evidence in a finding, adds `N of them are evidence in a finding.` after the links finish loading; wait for that text before a screenshot. Confirm with `{"text":"Delete","within":".modal-footer"}`.
