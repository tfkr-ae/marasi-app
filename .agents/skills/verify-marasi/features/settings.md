# Application settings

## Sub-features

- Vim, syntax mode, line wrapping (`wrap_mode`), default interface, and default port
- Waypoint management
- Chrome executable paths and profiles
- Upstream proxies (Upstream Proxy section): this machine's list in `upstream_proxies` of `marasi_config.yaml`, the open project's selection (`marasi`/`upstream_proxy.active` in `client_setting`), Edit (URL and CA), and Test
- Highlight colours and app labels (Highlights section): the 8 highlights' colours and app-wide labels, saved to `highlights` in `marasi_appconfig.yaml`, with Reset to defaults
- App default content-type exclusion (Content Types section): the types the Ledger hides in projects that follow the default, saved to `ledger_content_type_exclusion` in `marasi_appconfig.yaml`
- Maintenance section: Marasi's background jobs for the open project (search index, sitemap, formatted bodies) with their state, and Rebuild for the search index and the sitemap
- Build version displayed beside the page heading (`dev` in a local development build)
- Updates section: the Channel (`Release`/`Nightly`), the update status with `Check`, `Check automatically`, and `Reinstall` of the latest release; the global `Check for updates…` action (`⌘⇧U`, id `global.check-for-updates`) runs the same check
- Keybindings modal (`Configure Keybindings`): rebind menu actions per profile and platform, saved to the `keybindings` section of `marasi_appconfig.yaml`

## How to get to it (user POV)

Select the rail item titled `Settings`, or press `Command+,` from any route (`⌘S` is the Ledger's Search). The page shows `Marasi Settings`, the build version, and a sections list (`nav[aria-label="Settings sections"]`): Keyboard & Editor (default), Listener, Waypoints, Browser, Upstream Proxy, Highlights, Content Types, Maintenance, Updates and About. Only the selected section is rendered; pick one with `{"click":"nav[aria-label=\"Settings sections\"] button","hasText":"Waypoints"}`.

Shortcuts: every menu shortcut for this feature is a catalog action in context `global` (Settings has no page menu) in `frontend/src/lib/keybindings/catalog.js`; the Marasi menu (`⌘K`) on the page lists them with their current keys.

## Driving it with Chrome CDP

Run `scripts/drive.sh settings` for route proof. For persistence, toggle Vim and confirm `vim_enabled` changed in the isolated `marasi_appconfig.yaml`, then toggle it back and prove the original value was restored:

```json
{"name":"vim-off","steps":[{"click":"[data-testid=\"slide-toggle\"]"},{"waitSelector":"[role=switch][aria-checked=false]"}]}
```

The checkbox inside is `display:none`; read state from `[role=switch]`'s `aria-checked`. The toggle has no visible caption (its row reads `Vim mode`); use `section [role=switch]` (the rail's theme switch is also a `[role=switch]`).

Keybindings: `{"text":"Configure Keybindings"}` opens the modal (`[data-keybindings-modal]`). The sidebar has two columns: pick a page in `nav[aria-label=Page]` (for example `{"click":"nav[aria-label=Page] button","hasText":"WebSocket"}`), then a state in `nav[aria-label=State]` (`"hasText":"Stream tab"`); selecting a page selects its first state. Row controls have labels: `button[aria-label="Add binding to Ledger"]`, `button[aria-label="Remove ⌘+J from Ledger"]`, `button[aria-label="Reset Ledger"]`. Adding or re-recording a chip opens `[data-key-capture]`; send the combination with a `key` step. Escape cancels only the capture. Save closes the modal with a `Keybindings saved` toast; a failed save shows `[data-save-error]` and keeps the draft. Prove the result with the shortcut itself and the isolated YAML, then close with Cancel and `Discard` (or Escape when nothing changed) so doctor sees no residue:

```json
{"name":"kb-save","steps":[{"text":"Configure Keybindings"},{"waitText":"Every page"},{"click":"button[aria-label=\"Add binding to Ledger\"]"},{"waitSelector":"[data-key-capture]"},{"key":"cmd+j"},{"waitText":"Unsaved changes"},{"text":"Save"},{"waitText":"Keybindings saved"},{"key":"cmd+j"},{"waitPath":"/ledger"}]}
```

## Gotchas

- General settings persist to `marasi_appconfig.yaml`, Chrome settings to `marasi_config.yaml`, and waypoints to the project database.
- Address and port edits do not visibly restart the current listener.
- Chrome Paths and Chrome Profiles are both in the Browser section; the profiles table can sit below the fold with many paths, and the driver scrolls a unique match into view.
- Default interface and Default port (Listener section) persist on `change` (blur or Enter), not per keystroke. Both share `placeholder="Listener"`; use `aria-label="Default interface"` / `"Default port"`.
- Syntax highlighting is a three-button switch (`[role=radiogroup][aria-label="Syntax highlighting"]`); each button writes `syntax_mode` on click and the current one has `aria-checked=true`.
- Line wrapping is the same switch (`[aria-label="Line wrapping"]`) writing `wrap_mode`. Choosing a mode also sets the session Wrap lines toggle: on for Auto and Enabled, off for Disabled; a launch starts the toggle the same way. Editors fold every run of 10,000+ characters without a space, quote, angle bracket, `=`, `&` or `,` into a `.cm-long-string` placeholder (`… 2.4 MB · show`); a real mouse press on it shows the string. Wrapping counts only the lines left showing: under Auto, once a shown line is over 100,000 characters the editor stops wrapping and says so: the Ledger drawer's Wrap lines rail button shows an amber dot (`.ledger-drawer-wrap-suspended`), the Launchpad's Request and Response headers show `Not wrapped` (`.lp-wrap-suspended`), and `RequestResponseView` shows `not wrapped` beside Linewrap. Under Enabled a shown string wraps anyway. Prove it with a JSON response holding a 2.5 MB base64 string: under Auto, opening it and pressing its placeholder each have no long tasks; under Enabled the press wraps it and blocks the page for 1–2 s in headless Chrome. The Launchpad compare view does not fold; it stops wrapping a body with a line over the limit.
- Content Types lists the app default grouped by the Types menu's groups (Other last) in `#settingsDefaultContentTypes`: each group is a `section[data-group="…"]`, each value an `li[data-type="…"]` with a remove button `aria-label="Remove <type>"`. One sticky box at the top, `#settingsNewContentType`, both filters and adds: typing filters by value or group label and `#settingsContentTypeCount` reads `N of M match.`; a new `type/subtype` or `type/*` enables `Add <type>` and the line adds `Enter adds <type>.`; a value already in the list reads `Already hidden.`. Enter (or the button) adds and clears the box, Escape clears it; with it empty the line reads `N types hidden.`. Modified shortcuts such as `cmd+u` run from this box and every other Settings field; plain keys stay with the field. A project with its own list (edited in the Ledger's Types menu) ignores this list until reset.
- Highlights lists one row per highlight (`[data-highlight="N"]`): a colour input (`aria-label="Highlight N colour"`) and a label input (`aria-label="Highlight N label"`, placeholder the colour's name). Both save on `change`, so after `insert` blur the field (click the section heading, `{"click":"h3","hasText":"Highlights"}`) and wait for the label in the row's caption; Enter alone does not commit. The YAML gets `highlights: [{color, label?}, …]` (8 entries); `Reset to defaults` confirms first. A project's own label (set from the Ledger's Highlights menu) is a `ledger.highlight.N` client setting and does not show here.
- Maintenance lists `ListJobs()` in `#settingsJobs` (rows `tr[data-job="traffic_index|annotation_index|sitemap|prettified_move"]`, state `Complete`, `Building` or `Building · N of M`); the list polls every 2s while a job runs. `#settingsRebuildIndex button` and `#settingsRebuildSitemap button` (variant-soft, `Building…` and disabled while that job runs) open a confirm modal (`Rebuild the search index?` / `Rebuild the sitemap?`, confirm with `{"text":"Rebuild","within":".modal-footer"}`, since the page's own Rebuild buttons match too); confirming restarts the job, so its row turns `Building` and the Ledger's notices show until it finishes. Rebuilding the search index rebuilds both `traffic_index` and `annotation_index`. In a fresh scratchpad the jobs finish within a poll or two. On the 100k fixture the sitemap rebuild takes about a minute and the search index well over 30 minutes; the row reads `Building · N of M` in warning colour meanwhile.
- Updates (`/settings?section=updates`, the link the update panel uses) in a development build, which is what `launch.sh` runs: there is no Channel radiogroup and no `Latest release` row, the status line reads `Development builds don't check for updates`, `Check automatically` is disabled (its hidden `input[name=update-checks]` has `disabled`), and `Check` or `⌘⇧U` only toasts `Development builds don't check for updates`; nothing is written to `marasi_appconfig.yaml`. Checking, downloading, installing and the Channel switch need a signed release or nightly build. Proven:

```json
{"name":"updates-check","steps":[{"click":"nav[aria-label=\"Settings sections\"] button","hasText":"Updates"},{"waitText":"Check automatically"},{"waitText":"Development builds don't check for updates","within":"section"},{"waitNoSelector":"[role=radiogroup][aria-label=Channel]"},{"waitNoText":"Latest release"},{"text":"Check"},{"waitText":"Development builds don't check for updates","within":".snackbar-wrapper"}]}
```

- While an update is known (a release or nightly build only), the rail's Settings icon carries a dot or download ring and its title becomes `Settings · <status>` (for example `Settings · Update available: <version>`), so `drive.sh settings`, which clicks `[title="Settings"]`, cannot find it; it also links to `/settings?section=updates`.
- Upstream Proxy: the add row is `tfoot input` 1 (name) and 2 (URL), then `{"text":"Add Upstream Proxy"}`. The selection is `select[aria-label="This project's upstream proxy"]`: click it, then a bare `key` with the option's first letter (`d` for Direct). Test connects to `[aria-label="Test target"]` and shows `Connected` or the failure in the row's Last Test cell. Edit opens a modal (`Edit <name>`) whose URL field starts empty, because Marasi never returns credentials. Deleting the selected entry first asks `Remove <name>?`. Afterwards the select reads `<name> (not set up)` and `[data-testid=upstream-warning]` shows. To prove routing, run a local CONNECT proxy and an origin, send `curl --proxy http://127.0.0.1:18080` and read the proxy's log. A pair's route is in `request.upstream_proxy_name` and `upstream_proxy_address`, and a failed route gives a 502 and one ERROR row in `logs`.
- Row X and pencil buttons have `title="Delete"` / `title="Edit"`; find the `<tr>` with `hasText` first. Each table's add row is its `<tfoot>`.
- Adding a Chrome profile only appends YAML. Deleting a profile also removes `$configDir/chrome_profiles/<name>`. Directories appear later when Chrome starts.
- Keybinding conflicts show on the row (`… is also bound to …`) and block Save: `[data-save-blocked]` in the footer names one problem as `Profile · Platform · Page · State · Action: …` (with `(i of N problems)` when there are several), including problems on a profile or platform not on screen. `Show` switches to it; `Next` steps to the next problem in a fixed order (every profile, macOS before Windows / Linux) and switches to it. When the saved section failed to load (for example `version: 99`, set up by editing the isolated YAML and running `restart.sh`), Save first asks `Replace saved keybindings?` in `[role=alertdialog]`; its Cancel leaves the YAML untouched.
- The keybindings modal takes Escape and backdrop clicks over: they cancel a capture, dismiss an in-modal card, or ask `Discard changes?` before closing with unsaved edits. To simulate a failed save, make the isolated config directory unwritable (`chmod a-w`), and restore it before cleanup.
- Keybinding profiles: `{"text":"Manage"}` opens `[data-profile-menu]`; pick entries with `{"text":"Duplicate","within":"[data-profile-menu]"}`. Disabled entries keep their reason in `title` (for example `button[role=menuitem][disabled][title="The last profile cannot be deleted"]`). New Profile, Duplicate and Rename open `[data-profile-name]` with the name selected: `cmd+a`, `insert`, then `enter`. Delete and the platform Reset confirm in `[role=alertdialog]`. Switch the platform with `{"click":"[data-keybindings-modal] label.label select"}` then `{"key":"w"}` or `{"key":"m"}`. Windows / Linux chips read `ctrl+⇧+J`, so aria-labels are `Remove ctrl+⇧+J from Ledger`.
- Profile Import and Export (Manage menu) use native open/save dialogs that headless Chrome cannot operate. Launch with `MARASI_KEYBINDINGS_PROFILE_FILE=<absolute path> scripts/launch.sh`: both entries then skip the dialog and use that path. Export writes the file (toast `Exported <name> to <file>`). Import reads it on each click, so rewrite the file between imports to test other content. A success toasts `Imported <name>. It is not active; save to keep it.` and selects the profile. A rejected file opens `[data-profile-notice]` (`Profile not imported`, `<file>: <reason>`) and leaves the draft unchanged. The format is in `docs/keybinding-profile-format.md`.
- Ledger's palette lists only Ledger page actions; check global bindings (for example Ledger's `⌘+2`, or a binding you just saved) in the menu on Settings or Home.
